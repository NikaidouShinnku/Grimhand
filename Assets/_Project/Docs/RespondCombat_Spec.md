## 一、基本概念

| 术语 | 含义 |
|------|------|
| 应对卡 | 带 `parry` / `respond_defense` / `respond_status`，或带「条件效果」（`Condition != None`）的牌 |
| 配对 | 一张应对卡绑定「打到自己的第一张合法攻击卡」 |
| 成功应对 | 配对成功 → 减伤 / 特效 / 反击生效 |
| 失败应对 | 本回合没有合法攻击可配 → 只结算无条件效果（没有则无事） |
| 速度 | **不决定**应对与攻击谁先谁后；只影响其它牌在 baseline 中的顺序 |

---

## 二、配对规则（1对1 / 多对多 / 数量不等）

### 算法（按应对侧）

1. 把本方应对卡按**计划出牌顺序**排好。  
2. 对每张未配对的应对卡：在 baseline 里找**第一张**「会打到自己」的攻击卡。  
3. 配上后：该应对标记已用；该攻击仍可被**其他受击者**的应对再配对（AoE）。

| 场景 | 攻击 | 应对 | 配对结果 | 说明 |
|------|------|------|----------|------|
| 1对1 | A 打战士 | 战士 1 应对 | A↔战士应对 | 标准 |
| 1攻多应（同目标） | A 只打战士 | 战士 2 张应对 | **仅第 1 张**配 A；第 2 张失败 | **严格 1:1**，一张攻击只能配一张应对 |
| 1攻多应（AoE） | A 打全体 | 战士+法师各 1 | **仅计划中先出的那张**配 A；另一张失败 | 一张攻击卡全局只占一个应对坑 |
| 多攻 1 应 | A1、A2 都打战士 | 战士 1 应对 | 配**第一张**打到自己的（A1） | 按攻击在 baseline 的先后 |
| 多攻多应 | A1、A2 打战士 | 战士 2 应对 | A1↔应对1，A2↔应对2 | 按双方计划顺序依次配 |
| 应 > 攻 | 1 张打战士 | 3 张应对 | 1 成功 + 2 失败 | 失败张无条件效果仍结算 |
| 攻 > 应 | 3 张打战士 | 1 张应对 | 只挡第 1 张；后 2 张正常打 | — |
| 打别人 | A 打法师 | 战士应对 | 不配，失败 | 必须打到应对者本人 |
| 非攻击 | 敌方加甲 | 战士应对（parry） | 不配，失败 | `parry` 只配攻击 |

敌方应对（终焉守护等）对称：玩家攻击打到该敌人 → 配该敌人的应对。

## 三、结算顺序（逻辑，与速度无关）

对每一对「攻击 ↔ 应对」：

| 步骤 | 做什么 | 数值 | 演出 |
|------|--------|------|------|
| 0 预武装 | 攻击结算前登记减伤 / 武装 | 保证伤害算对 | **无立绘** |
| 1 攻击结算 | 攻击者出牌、造成伤害（已减伤） | 扣血 / 破甲 | 攻击者到中间 **攻击** |
| 2 受击反应 | — | — | 应对者**原位** Defense + blocking |
| 3 应对副作用 | 护甲、清能量、上状态等 | 按卡面 | **不要**再让应对者跑去中间做防御姿势 |
| 4 反击（若有） | 弹反伤害 | 对攻击者造成伤害 | 应对者到中间 **攻击** |

整回合：按 schedule 逐对播放；未配对的应对单独走「失败结算」。

## 四、演出规范（铁壁弹反等）

### 正确：有减伤 + 弹反（如铁壁弹反）

| 序 | 谁 | 动作 | 姿态 / 特效 |
|----|----|------|-------------|
| 1 | 攻击者 | 到中间 | **攻击** |
| 2 | 应对者 | **留在原位** | **Defense + blocking（同时）** |
| 3 | — | 扣血数字 / 破甲 | 可叠在 blocking 后 |
| 4 | 攻击者 | 归位 | Idle |
| 5 | 应对者 | 到中间 | **攻击**（反击） |
| 6 | 原攻击者 | 受击 | Hit |
| 7 | 应对者 | 归位 | Idle |

### 正确：只有减伤、无弹反（如终焉守护）

| 序 | 谁 | 动作 |
|----|----|------|
| 1 | 攻击者 | 中间攻击 |
| 2 | 应对者 | **原位** blocking + 减伤表现 |
| 3 | 攻击者 | 归位 |
| 4 | （可选） | 护甲数字 / 清能量等 UI，**禁止**应对者再中间 Defense 出场 |

### 失败应对（多余的应对卡）

| 有无条件效果 | 演出 |
|--------------|------|
| 无 | 牌进弃牌 / 消耗，**无立绘、无 blocking** |
| 有（如仍给护甲） | 可按普通防御牌：到中间 Defense → 加甲 → 归位 |

### 禁止再犯

| 错误 | 正确 |
|------|------|
| 成功应对发 `PortraitPoseChanged` + `CardType.Defense` 导致中间防御出场 | 成功应对**跳过**中间防御出场 |
| 只播 blocking、不播反击攻击 | 有弹反时攻击者归位后直接 **Attack** 出场反击 |
| 速度决定应对插队到攻击前 | 始终攻击先、应对副作用 / 反击后 |

## 五、效果类型对照

| 效果类型 | 何时写入逻辑 | 何时表现 | 例子 |
|----------|--------------|----------|------|
| 百分比减伤 | 攻击前预登记 | 受击时原位 blocking | 铁壁 30%、终焉 50% |
| 弹反 / 反击伤害 | 攻击后入队 | 攻击归位后，应对者 **攻击** 出场 | 铁壁弹反 100% |
| 无条件护甲 | 应对成功结算步 | 数字 / UI，勿强制中间防御 | 终焉守护 +8 |
| 清能量 / 禁回复 | 应对成功触发 | 能量条 / 状态 | 终焉守护 |
| 上状态 / 减速攻击者 | 应对成功 | 状态图标 | 见招拆招等 |

## 六、玩家侧 vs 敌方侧

| | 玩家应对（铁壁等） | 敌方应对（终焉守护等） |
|--|-------------------|----------------------|
| 配对 | 打到自己的敌方攻击 | 打到自己的玩家攻击 |
| 减伤 | `RespondMitigation` 层 | `DefenderRespondArm` 武装 |
| 反击 | `PendingParryStrikes` → 攻击出场 | 通常无弹反 |
| 失败多余卡 | 静默或仅无条件效果 | 同左（终焉仍可给护甲） |

## 七、AoE / 溅射

| 情况 | 行为 |
|------|------|
| AoE 打中多人 | **一张攻击仍只配一张应对**（计划中最先出的合法应对）；其余应对失败 |
| 溅射打到身后 | 只有**实际吃到伤害**的角色才能用自己的应对配这张攻击；且该攻击仍只能配一张 |
| 嘲讽改目标 | 以最终真实目标为准配对 |

## 八、实现检查清单（改代码前必读）

1. `RespondResolutionPlanner`：攻击步在前，配对应对步在后；**一张攻击 ↔ 一张应对（严格 1:1）**。  
2. `BattleEngine.ResolveTurn`：攻击前 `PreparePairedRespondMitigation`；成功应对步**不发**防御用 `PortraitPoseChanged`。  
3. `ResolvePendingParriesForEnemyCard`：反击用 `CardType.Attack` 出场。  
4. `BattlePortraitDirector.PlayDamageReactionOnly`：`HadRespondDefense` → 原位 Defense + blocking。  
5. 失败应对且无条件效果：不强制出场。

## 九、总结（一句话）

**严格 1:1：一张攻击只配一张应对。** 先攻击到中间 → 原位 blocking → 归位后可选反击；配对结算完减伤/武装清掉；多出的应对失败（无条件效果才结算）。
