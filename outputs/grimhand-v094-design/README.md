# Grimhand v0.94 设计评审包

> 第二轮评审已撤回第一版三张橙卡与旧受击图的合格判断。新角色设计以《角色重设计_第二轮.md》为准；下面与同目录旧Excel保留为第一轮记录，尚未全部同步第二轮内容，不是已批准方案。revision-02目录中的新图仍是候选，不是已通过整套风格验收。

这是平衡评估与第六位角色的设计提案，不是已落地的可玩版本。原 v0.93 工作簿和游戏运行代码均不覆盖。

## 新角色：裂斧 · 荒原狂战士

成人女性人类，短赤褐发、收腰V领皮革战甲、毛领、暗红开衩战裙与金属护腿，双手战斧。用户已确认这一版魅惑程度，要求进一步贴近原角色的粗像素与紧凑头身比例。定位为前排承压后的反攻，不抢战士的保护/应对体系，也不复制恶魔的主动献祭。

基础HP76，每级+6（20级190），SPD5；仍然只有HP与SPD两个基础属性。狂怒是角色专属状态，不增加第三项角色属性。基础血量略低于战士，速度也更慢，不能同时拿走坦度、先手和输出三项优势。

### 狂怒的完整规则（新增，待审批）

- 每场开局0，上限4。自身因敌方攻击牌实际损失HP后获得1点；同一张敌牌无论多段/AOE只触发一次，此来源每回合最多触发2次。
- 护甲完全吸收、毒/烧、反伤、献祭、友伤、自伤均不触发。满上限时不存溢出。死亡不保留。
- 从第2回合开始，回合开始先流失1点，再执行其他开始效果。结算中取得的狂怒不改变本轮速度顺序。
- 消耗在卡牌实际结算前进行；“最多消耗N”读取当时可用量，不足不妨碍打出基础效果。计划阶段显示的是估计值，不保证未来受到伤害。
- 每个动作的消耗只发生一次；AOE和多段共享该次消耗。伤害加成进入基础威力，再按现有增伤、减伤、护甲、虚化结算。
- 《侧斧卸力》《专注怒意》等显式额外获取不受“敌方攻击直接获得2点”子上限，但受总上限4。每张牌/被动分别有每回合触发限制。
- 不提供狂怒兑换能量、无限抽牌、无消耗治疗或死亡免疫。《猎者喘息》消耗后只能一次治疗，不能通过治疗反触发狂怒。

初始牌组7张：《裂斧斩》3、《铁臂架挡》2、《反击重劈》1、《压住怒火》1。共享牌库、共享能量、目标射程、死亡牌处理均沿用现有流程。32张职业牌、11个天赋节点及升级表详见工作簿新增页；每槽只装备一个天赋，不自动获得全部节点。

### 三种构筑，不是三套新规则

稳守反击：架挡与有限应对积累狂怒，用《反击重劈》《裂盔》集中输出。分散攻击：横斧/旋斧AOE，牺牲单体效率换多目标收益。节制循环：淬怒/不息攻势奖励每回合第一次合理花怒，不产生同回合抽牌连锁。没有任何牌默认“有狂怒就全回合增伤”。

## 平衡结论的边界

正式能量8、每回合回能4、抽5、手牌10，使用真实角色初始牌组与真实怪物组合，10种三人组合、两种简单出牌策略、6个种子（轮换3种站位）。共4,680场，每场独立满血、等级1、无遗物/天赋/升级；排除权重0的教程。高层仅用于压力测试，不能当作玩家自然成长后的难度判断。

首层普通战480场均获胜，其中11场有人倒下；首层精英战240场中222场获胜，111场有人倒下。精英战的连战损耗值得优先验收，不能只看92.5%的独立满血胜率。两组都不是玩家真实通关率；没有按怪物出现权重加权，也没有以抽样独立性为前提给出置信区间。

新角色另有18项设计模型断言：狂怒上限、每牌/每回合获取、来源过滤、流失、一次消费覆盖AOE及多段，以及32张牌的数据完整性。它们验证提案内部逻辑，不代表游戏里已经实现和测试该角色。

本次没有运行完整远征选路、商店、奖励选择、成型毒/献祭/虚化组合、Boss全机制，亦没有真人试玩。因此不能承诺“平衡已完美”或给出真实通关率。工作簿将静态可证的资源交互与待实测推断分开；不根据简单AI排名直接改弱角色。

优先评审的是永恒虚无代价被虚化抵消、神圣轮回移除消耗、无尽血刃指数增长、自毒换能量与治疗的收益叠加。这些是设计上限问题，不擅自修改你已确认的虚化、献祭、治疗规则。

## 素材与接入要求

当前画面系统实际需要Idle/Attack/Defense/Hit/Death五种姿态、CardProfile半身卡像，以及待机帧或GIF；不要求每个攻击都配完整逐帧动画。新角色共用现有卡框、关键词图标、字体和牌面系统；不为32张牌复制32张角色头像。

素材状态及具体文件以工作簿“素材与验收”和包内ART_REVIEW.md为准。PNG草图能导入不代表与现有角色完全一致，也不代表动画已完成。未通过比例/像素/一致性检查的图片不得加入正式素材目录。

批准设计后再接入角色枚举/标准ID、成长、牌池/掉落、天赋、存档白名单、营地解锁、CardDescriptionCatalog、EffectActionSpec/狂怒事件及预览、CharacterVisualCatalog。必须补狂怒一次/多段/AOE/护甲/虚化/死亡/离场/回合边界、资源不足、升级文案与存读档测试，再做Unity画面与完整远征验收。
